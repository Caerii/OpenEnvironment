# UV Quick Start Guide

Fast track for getting the backend running with [uv](https://github.com/astral-sh/uv).

## Why `uv`?

- ⚡ **10-100x faster** than pip
- 🔒 **Reproducible builds** with `uv.lock`
- 🦀 **Rust-powered** dependency resolver
- 📦 **All-in-one** tool (replaces pip, pip-tools, virtualenv, pyenv)
- 🎯 **Drop-in replacement** - works with existing `pyproject.toml`

## Install `uv`

**Windows (PowerShell):**
```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**macOS/Linux:**
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Verify:**
```bash
uv --version
```

## First-Time Setup

```bash
cd server

# Create .venv + install deps + generate uv.lock
uv sync
```

That's it! You now have:
- `.venv/` - Virtual environment (gitignored)
- `uv.lock` - Locked dependency tree (commit this!)

## Run the Server

### Option 1: Direct command
```bash
cd server
uv run uvicorn server.main:app --host 0.0.0.0 --port 8000 --reload
```

### Option 2: Use launcher script
```bash
# Windows
.\start-backend-uv.ps1

# macOS/Linux
chmod +x start-backend-uv.sh
./start-backend-uv.sh
```

## Common Commands

### Add a dependency
```bash
cd server
uv add python-dotenv
# Automatically updates pyproject.toml + uv.lock + installs
```

### Remove a dependency
```bash
uv remove python-dotenv
```

### Update all dependencies
```bash
uv lock --upgrade
uv sync
```

### Install dev dependencies
```bash
uv sync --all-extras
# Installs ruff, pytest, etc.
```

### Run scripts without activating venv
```bash
# No need for "source .venv/bin/activate"!
uv run python -c "import numpy; print(numpy.__version__)"
uv run ruff check .
uv run pytest
```

### Activate venv manually (if needed)
```bash
# Windows
.\.venv\Scripts\Activate.ps1

# macOS/Linux
source .venv/bin/activate
```

## Key Differences vs pip

| Task | pip | uv |
|------|-----|-----|
| Create venv | `python -m venv .venv` | `uv venv` (or `uv sync`) |
| Activate venv | `source .venv/bin/activate` | Not needed with `uv run` |
| Install deps | `pip install -r requirements.txt` | `uv sync` |
| Add package | `pip install pkg` + manual edit | `uv add pkg` |
| Run script | `python script.py` | `uv run python script.py` |
| Lock deps | `pip freeze > requirements.txt` | `uv lock` (automatic) |

## Files Explained

### `pyproject.toml`
- Source of truth for dependencies
- Replaces `requirements.txt` (though we keep both for compatibility)
- Defines project metadata, dev tools, scripts

### `uv.lock`
- **Commit this!** - Ensures reproducible builds
- Auto-generated by `uv sync` or `uv lock`
- Contains exact versions + hashes of all transitive deps

### `requirements.txt`
- Legacy compatibility file (kept in sync for pip users)
- uv ignores this if `pyproject.toml` exists

## Troubleshooting

### Import errors: `ImportError: attempted relative import`
**Problem:** Running `uvicorn main:app` instead of `uvicorn server.main:app`

**Fix:** Always include the `server.` package prefix:
```bash
# ✅ Correct
uv run uvicorn server.main:app --reload

# ❌ Wrong
uv run uvicorn main:app --reload
```

### `uv: command not found`
**Problem:** Shell can't find uv after install

**Fix (Windows PowerShell):**
```powershell
$env:Path += ";$env:USERPROFILE\.cargo\bin"
refreshenv
```

**Fix (macOS/Linux):**
```bash
source $HOME/.cargo/env
# Or restart terminal
```

### Slow NumPy/SciPy install
**Problem:** Compiling from source (no binary wheels for your Python/OS combo)

**Fix:** Use Python 3.10-3.12 on x86_64/ARM64:
```bash
echo "3.11" > .python-version
uv sync
```

### Wrong Python version
**Problem:** uv using system Python instead of your preferred version

**Fix:** Set version explicitly:
```bash
echo "3.11" > .python-version
uv sync
```

Or specify on sync:
```bash
uv sync --python 3.11
```

## Advanced: Pin Python Version

Add to `pyproject.toml`:
```toml
[project]
requires-python = ">=3.11,<3.13"
```

Or create `.python-version`:
```bash
echo "3.11.9" > .python-version
uv sync
```

uv will automatically download the right Python if needed!

## Comparison: Traditional Flow vs uv

**Traditional (pip):**
```bash
python -m venv .venv
source .venv/bin/activate  # or Windows equivalent
pip install -r requirements.txt
uvicorn server.main:app --reload
```

**With uv:**
```bash
uv sync
uv run uvicorn server.main:app --reload
```

That's 2 commands vs 4, and the uv version is **~50x faster** on first install.

## Migrating from pip

Already have a working pip setup? No problem:

```bash
# Keep your existing .venv or let uv create a new one
cd server

# uv reads pyproject.toml and creates uv.lock
uv sync

# Done! Your .venv now managed by uv
uv run uvicorn server.main:app --reload
```

Your `requirements.txt` stays for pip users, but you get `uv.lock` for reproducibility.

## Pro Tips

1. **Commit `uv.lock`** - It's your reproducible build manifest
2. **Use `uv run`** - Skip manual venv activation
3. **Add deps with `uv add`** - Auto-updates all files
4. **Set Python version** - `.python-version` or `requires-python` in pyproject
5. **CI/CD friendly** - `uv sync` is idempotent and cached-aware

## Still Want pip?

No problem! The project supports both:

```bash
cd server
python -m venv .venv
source .venv/bin/activate  # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn server.main:app --reload
```

Both `requirements.txt` and `pyproject.toml` are kept in sync.
